# EnglishMaster — Supabase backend

Target project: **`nefpgqoykfndjvrdultp`** ("EnglishMaster AI", eu-west-1).

This directory is a separate Supabase CLI workdir. The top-level `supabase/` directory belongs to
the older Lovable web app (project `eismzvkrtisofnfdubqn`) and must **not** be pushed to this
project — its migrations contain known security defects (see `docs/phase-1-audit.md`).

```
backend/supabase/
  config.toml                 CLI settings (auth policy for local dev / config push)
  migrations/                 versioned schema, RLS and RPCs
  seed/assessment_questions.sql   generated from public/data/questions.csv
  tests/database/*.test.sql   pgTAP suite
scripts/db/
  build_question_seed.py      regenerates the seed
  supabase_stubs.sql          minimal Supabase emulation for plain Postgres
  test-local.sh               migrations + seed + pgTAP on a throwaway Postgres
```

## Schema (phase 2 slice)

| Table | Purpose | Who can read | Who can write |
|---|---|---|---|
| `profiles` | display name, UI language, account status | owner; admin | `update_my_profile()` only (name, language) |
| `user_roles` | `student` / `teacher` / `admin` | owner (own roles); admin | nobody via API; sign-up trigger adds `student`; admin bootstrap |
| `activity_logs` | append-only events, server timestamps | admin | SECURITY DEFINER functions only; `UPDATE` blocked by trigger, `UPDATE/DELETE` revoked from `service_role` |
| `assessment_questions` | question bank **with answer keys** | teacher, admin | nobody via API yet (seed / SQL) |
| `assessment_attempts` | one practice session; id generated by the client | owner; admin | `submit_practice_response()` only |
| `assessment_responses` | server-scored answers; id = idempotency key | owner; admin | `submit_practice_response()` only |

RLS is enabled on every table; `anon` has no table privileges. Helper functions live in schema
`private`, which the Data API does not expose.

Staff RPCs (`20261019203557_staff_tools`, role checked on the server, every change logged):

| RPC | Allowed for | Notes |
|---|---|---|
| `get_my_roles()` | any signed-in user | own roles only |
| `admin_list_users(p_search, p_limit, p_offset)` | admin | name/e-mail search (wildcards escaped), roles, practice totals |
| `admin_set_role(p_user_id, p_role, p_granted)` | admin | teacher/admin only; cannot remove own admin role |
| `admin_set_account_status(p_user_id, p_status)` | admin | cannot change own status |
| `admin_recent_activity(p_limit)` | admin | activity log with actor names |
| `staff_review_question(p_question_id, p_review_status, p_status)` | teacher, admin | approve / unreview; publish / retire |

Teachers and admins also read `assessment_questions` (with answer keys) directly; RLS allows no one else.

Student RPCs (all require a signed-in, non-suspended user):

* `get_practice_questions(p_cefr_level, p_after, p_limit)` — published questions **without**
  `correct_option`/`explanation`, keyset-paginated, max 200 per page.
* `submit_practice_response(p_response_id, p_attempt_id, p_question_id, p_chosen_option, p_client_answered_at)` —
  scores on the server, idempotent on `p_response_id`; first answer per question per attempt wins;
  120 responses/minute/user limit; logs `practice.response_submitted`.
* `get_my_practice_summary()` — per-level answered/correct from stored rows.
* `update_my_profile(p_display_name, p_interface_language)`.

Full request/response contract: [`docs/api-contract.md`](../docs/api-contract.md).

Exams and certificates (`20261020030000_exams_and_certificates`):

| RPC | Who | Notes |
|---|---|---|
| `get_learning_overview()` | learner | per level: published, distinct answered, latest-correct, required, exam unlocked / in progress / next attempt, certificate |
| `get_learner_profile()` | learner | name, placement level, total answers, day streak |
| `start_level_exam(p_cefr_level)` | learner | 20 random published questions, 30 min; resumes an unfinished attempt; refusals use SQLSTATE P0001 with `hint` = `not_unlocked` / `retry_later` / `already_certified` / `not_enough_questions` |
| `submit_level_exam(p_attempt_id, p_answers)` | owner | server marks; >= 80% issues a certificate; idempotent; late (> 2 min grace) = expired |
| `start_placement_test()` / `submit_placement_test(...)` | learner | 3 questions per level A1–C2; recommends the level after the highest one passed with >= 2/3 |
| `get_my_certificates()` | learner | own certificates |
| `verify_certificate(p_code)` | **anyone** | returns only the printed facts of the certificate with that code |

Edge function `verify-certificate` (verify_jwt off) prints the result of `verify_certificate` as
plain text; it is what the QR code on a certificate opens.

Media, authoring and names (`20261020090000_media_names_authoring`):

* `assessment_questions.passage / media_type / media_path / media_caption`; public bucket
  `question-media` (uploads by teachers/admins only); `get_practice_questions_v2` returns them.
* `staff_create_question(...)` (publish now or draft), `staff_publish_drafts(level)`,
  `staff_set_display_name(user, name)` (teacher/admin; issued certificates keep their name).
* `admin_list_users` is readable by teachers; role and status changes stay admin-only.

Certificate approval (`20261020160000_certificate_approval`): a passed level exam creates a
*pending* certificate; it is not downloadable and does not verify until a teacher or admin approves
it with `staff_review_certificate` (listed by `staff_list_certificates`). Nobody can review their own
certificate; approval uses the learner's current name; after a rejection the exam can be taken
again. `get_learning_overview_v2` adds `certificate_status`.

Question edit/delete (`20261020180000_question_edit_delete`): `staff_update_question` (teacher or
admin) bumps the version when prompt, options, key, passage, media or level change;
`staff_delete_question` (admin) deletes an unused question or archives an answered one
(`deleted_at`, retired), so answer history stays valid.

Account deletion (`20261021090000_account_deletion`): `delete_my_account()` lets a learner delete their
account and everything linked to it (Google Play requirement). Staff cannot self-delete; an admin removes
the role first. It also works around `activity_logs` being append-only (the FK's SET NULL is an update).

Auth email links: password-reset and sign-up confirmation emails redirect to
`app.englishmaster://auth-callback` (the app opens and finishes sign-in; recovery shows "choose a new
password"). In the dashboard, Authentication → URL Configuration must list it under **Redirect URLs**,
and the **Site URL** should be set to the same value (the default `http://localhost:3000` leads nowhere).

Permissions at a glance: **learner** — practise, exams, own profile and certificates; **teacher** —
plus learner list and name corrections, question review/authoring/editing/publishing, certificate
approval; **admin** — plus deleting questions, roles, suspensions and the activity log.

Topics (`20261020120000_question_topics`): `get_practice_questions_v3` = v2 plus `tags`, so the app
can offer practice by topic (Life in the UK, Kurdistan, stories/dialogues, history and nature,
pictures/videos) offline. Content batch `ai-batch-03` (114 drafts: stories, dialogues and facts on
the UK — Life in the UK test topics — and Kurdistan) is tagged `life_in_uk`, `kurdistan`, `story`,
`dialogue`, `history`, `culture`, `nature`, `world_knowledge`.

Content pipeline: `content/questions/ai-batch-*.json` and `content/media/**` are published by the
**EnglishMaster content** workflow on push: media are uploaded to `question-media` (upsert) and new
questions are inserted as drafts with PostgREST `resolution=ignore-duplicates`, so existing rows
(and teachers' decisions) are never changed. The SQL seeds are kept for local tests.

## Question content

`scripts/db/build_question_seed.py` builds the seed from `public/data/questions.csv`:

* 620 rows whose `source` is an **OOPT** document (Oxford Online Placement Test samples) are
  excluded — redistribution rights have not been established.
* The 3,380 "generated" rows are template variants of only **85 distinct sentences** (same prompt
  with shuffled or swapped distractors, plus a `(vNN)` suffix). The generator keeps one item per
  (level, prompt), preferring variants without filler options such as `am (alt)`.
* One prompt (*"This phone is ___ than my old one"*) is keyed to four different answers across its
  variants and is dropped as ambiguous.
* One wrong explanation ("carry out" = "find by chance") is corrected in
  `EXPLANATION_FIXES`; the CSV is unchanged.
* A manual review of all 84 items (2026-10-19) found wrong keys (e.g. *"My brother ___ to school"* keyed
  `works`), second correct options, `(alt)` fillers and unfinished template sentences. 32 items are
  corrected in `ITEM_FIXES`; options keep their order so the keyed letter does not change.
* Result: **84 items** — A1 25, A2 5, B1 11, B2 12, C1 16, C2 15.
* Every seeded item is `status = 'published'` (usable for practice) but `review_status = 'unreviewed'`;
  the app labels them. This is a pipeline-test bank, not a curriculum: real, reviewed content is
  required before placement or certificates.

### AI-drafted batches

`content/questions/ai-batch-*.json` holds multiple-choice items drafted with Claude (answer, three
distractors, explanation). `scripts/db/build_ai_question_seed.py` validates them (one `___` gap,
four distinct options, no duplicate prompt), shuffles option order deterministically and writes
`seed/assessment_questions_ai_batch_*.sql`.

* Imported as `status = 'draft'`, `review_status = 'unreviewed'`, `source = 'ai-draft:<batch>'`:
  **students cannot download them** until a teacher taps *Approve and publish* in Staff tools.
* Re-running the seed only updates rows that are still unreviewed drafts, so a teacher's decision
  is never overwritten.
* Batch 01: 125 items — A1 15, A2 30, B1 30, B2 20, C1 15, C2 15 (grammar and vocabulary).
  AI drafts can contain mistakes or more than one defensible answer; review is required.

## Running the database tests locally (no Docker needed)

Requirements: PostgreSQL ≥ 16 server binaries, `pgtap`, `pg_prove`
(Ubuntu: `apt-get install postgresql-16 postgresql-16-pgtap libtap-parser-sourcehandler-pgtap-perl`).

```bash
python3 scripts/db/build_question_seed.py   # only after changing the CSV
scripts/db/test-local.sh
```

With Docker available, the Supabase CLI can run the same suite against the real local stack:
`supabase start --workdir backend && supabase test db --workdir backend`.

## Applying to a hosted project

```bash
supabase link --project-ref nefpgqoykfndjvrdultp --workdir backend
supabase db push --workdir backend                 # applies migrations/
psql "$DATABASE_URL" -f backend/supabase/seed/assessment_questions.sql   # idempotent upsert
```

Then, in the dashboard:

1. **Auth → Providers → Email**: keep "Confirm email" on; set minimum password length to 8.
2. **Auth → URL configuration**: the password-reset e-mail links to the *Site URL*. A reset landing
   page for this project does not exist yet (see open items).
3. **Advisors → Security**: should report no findings.

### Admin bootstrap (one time)

1. Sign up normally (app or dashboard) with the owner's e-mail.
2. In the SQL editor (runs as `postgres`): `select private.bootstrap_first_admin('owner@example.com');`
   It refuses to run once any admin exists and is not executable by `anon`, `authenticated` or `service_role`.
