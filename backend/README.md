## Schema (phase 2 slice)

| Table | Purpose | Who can read | Who can write |
|---|---|---|---|
| `profiles` | display name, UI language, account status | owner; admin | `update_my_profile()` only (name, language) |
| `user_roles` | `student` / `teacher` / `admin` | owner (own roles); admin | nobody via API; sign-up trigger adds `student`; admin bootstrap |
| `activity_logs` | append-only events, server timestamps | admin | SECURITY DEFINER functions only; `UPDATE` blocked by trigger, `UPDATE/DELETE` revoked from `service_role` |
| `assessment_questions` | question bank **with answer keys** | teacher, admin | nobody via API yet (seed / SQL) |
| `assessment_attempts` | one practice session; id generated by the client | owner; admin | `submit_practice_response()` only |
| `assessment_responses` | server-scored answers; id = idempotency key | owner; admin | `submit_practice_response()` only |

RLS is enabled on every table; `anon` has no table privileges. Helper functions live in schema
`private`, which the Data API does not expose.

RPCs (all require a signed-in, non-suspended user):

* `get_practice_questions(p_cefr_level, p_after, p_limit)` — published questions **without**
  `correct_option`/`explanation`, keyset-paginated, max 200 per page.
* `submit_practice_response(p_response_id, p_attempt_id, p_question_id, p_chosen_option, p_client_answered_at)` —
  scores on the server, idempotent on `p_response_id`; first answer per question per attempt wins;
  120 responses/minute/user limit; logs `practice.response_submitted`.
* `get_my_practice_summary()` — per-level answered/correct from stored rows.
* `update_my_profile(p_display_name, p_interface_language)`.

Full request/response contract: [`docs/api-contract.md`](../docs/api-contract.md).

## Question content

`scripts/db/build_question_seed.py` builds the seed from `public/data/questions.csv`:

* 620 rows whose `source` is an **OOPT** document (Oxford Online Placement Test samples) are
  excluded — redistribution rights have not been established.
* The 3,380 "generated" rows are template variants of only **85 distinct sentences** (same prompt
  with shuffled or swapped distractors, plus a `(vNN)` suffix). The generator keeps one item per
  (level, prompt), preferring variants without filler options such as `am (alt)`.
* One prompt (*"This phone is ___ than my old one"*) is keyed to four different answers across its
  variants and is dropped as ambiguous.
* One wrong explanation ("carry out" = "find by chance") is corrected in
  `EXPLANATION_FIXES`; the CSV is unchanged.
* Result: **84 items** — A1 25, A2 5, B1 11, B2 12, C1 16, C2 15. 5 still contain an `(alt)` filler option.
* Every seeded item is `status = 'published'` (usable for practice) but `review_status = 'unreviewed'`;
  the app labels them. This is a pipeline-test bank, not a curriculum: real, reviewed content is
  required before placement or certificates.

## Running the database tests locally (no Docker needed)

Requirements: PostgreSQL ≥ 16 server binaries, `pgtap`, `pg_prove`
(Ubuntu: `apt-get install postgresql-16 postgresql-16-pgtap libtap-parser-sourcehandler-pgtap-perl`).

```bash
python3 scripts/db/build_question_seed.py   # only after changing the CSV
scripts/db/test-local.sh
```

With Docker available, the Supabase CLI can run the same suite against the real local stack:
`supabase start --workdir backend && supabase test db --workdir backend`.

## Applying to a hosted project

```bash
supabase link --project-ref nefpgqoykfndjvrdultp --workdir backend
supabase db push --workdir backend                 # applies migrations/
psql "$DATABASE_URL" -f backend/supabase/seed/assessment_questions.sql   # idempotent upsert
```

Then, in the dashboard:

1. **Auth → Providers → Email**: keep "Confirm email" on; set minimum password length to 8.
2. **Auth → URL configuration**: the password-reset e-mail links to the *Site URL*. A reset landing
   page for this project does not exist yet (see open items).
3. **Advisors → Security**: should report no findings.

### Admin bootstrap (one time)

1. Sign up normally (app or dashboard) with the owner's e-mail.
2. In the SQL editor (runs as `postgres`): `select private.bootstrap_first_admin('owner@example.com');`
   It refuses to run once any admin exists and is not executable by `anon`, `authenticated` or `service_role`.
